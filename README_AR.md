# OfflineStore v0.5 — مراجعة سلامة وسهولة استخدام (Preview)

**تنبيه: هذه نسخة تطويرية وليست برنامجًا محاسبيًا معتمدًا للمحل.**

## جديد الإصدار 0.5
- فحص `PRAGMA quick_check` و`foreign_key_check` عند كل تشغيل قبل فتح واجهة البيع. عند وجود خلل، يُمنع العمل بدل مواصلة التسجيل على قاعدة تالفة.
- تمنع سلة البيع طلب كميات أكثر من الرصيد بعد احتساب ما أُضيف للفاتورة نفسها؛ ويُعاد فحص الرصيد داخل معاملة الاعتماد النهائية.
- رفض أجزاء القطعة للأصناف المعدودة، ورفض بيع الكاشير بسعر صفر حتى لو السعر محفوظ صفرًا، مع السماح للمدير بتسعير خاص وفق صلاحياته.
- شاشة البيع توضح الرصيد والمتبقي والخطوات، وتطلب تأكيدًا مستقلًا قبل اعتماد الفاتورة.
- دعم كتابة الأرقام العربية والهندية في حقول المال والكمية، واختصارات F2 للمبيعات وF5 للتحديث، وEnter لبحث الباركود اليدوي.
- 50 اختبار SQLite/سلامة/واجهات ناجح محليًا، مع مشروع 11 اختبار C# لحسابات الأموال وتحويل الوحدات ضمن بناء Windows.

**لا تُسجل النسخة الحالية النقدية أو الحسابات الآجلة أو المرتجعات أو الربح المحاسبي المعتمد.** لا تستخدم بيانات حقيقية قبل إكمال هذه المكونات واختبارات الأجهزة وWindows.

# OfflineStore v0.4 — نسخة تطويرية من برنامج بيع ومخزون محلي

**الحالة: مصدر قابل للبناء وليس برنامجًا تجاريًا نهائيًا.** أضفنا وحدات بيع/شراء متعددة، وحسابات موظفين وصلاحيات، وتنبيهات نقص المخزون، وبحثًا بالباركود/SKU، واستقبال قارئ باركود تسلسلي COM/RS-232. اختبارات SQLite الآلية ناجحة محليًا؛ لم يتم بناء WPF أو اختبار EXE على Windows 7/10/11 في بيئة الإنشاء الحالية.

## مثال للعمليات

صنف شاي: الوحدة الأساسية «قطعة» وسعرها 15.00؛ «دستة» = 12 قطعة وسعرها 170.00؛ «كرتونة» = 48 قطعة وسعرها 600.00. **العامل والسعر يخصان الصنف نفسه**؛ لا تفترض أن كل كرتونة تحتوي 48 قطعة.

- عند إضافة فاتورة شراء 2 كرتونة، يزيد المخزون **96 قطعة**.
- عند بيع كرتونة و3 قطع، ينقص **51 قطعة**، ويصبح الرصيد **45 قطعة**.
- إجمالي بيع الكرتونة و3 قطع = **645.00** (600 + 3×15)، وليس 51×15.
- فاتورة البيع تحفظ الوحدة والكمية والسعر وتحويلها وقت البيع. تغيير السعر لاحقًا لا يغير الفواتير المعتمدة.
- يظهر تنبيه إذا كان الرصيد أصغر من أو يساوي «حد إعادة الطلب» المخصص للصنف. صفر يعني تعطيل التنبيه.
- الباركود اختياري للقطعة أو العبوة؛ يمكن للكاشير إدخال الباركود/كود الصنف لإظهار السعر المسجل للوحدة.

## قارئ الباركود Serial / COM (جديد في v0.4)

- **التشغيل الافتراضي للماسح معطّل** حتى يتم إعداد الجهاز واختباره. قارئ RS-232 ذو وصلة سيريال أو قارئ USB بنمط **Virtual COM** مدعومان نظريًا باستخدام مكتبة Windows `System.IO.Ports.SerialPort` بدون إنترنت. قارئ USB بنمط Keyboard HID لا يحتاج منفذ COM، ويمكنه إدخال الباركود في حقل البحث اليدوي.
- افتح «الإعدادات ← إعدادات الماسح واختبار القراءة» من حساب **ADMIN**، واختر المنفذ (`COM1` / `COM3` ...)، `Baud Rate`، و`Data Bits` و`Parity` و`Stop Bits` و`Handshake` **كما هي في دليل الجهاز**. القيم الابتدائية 9600 / 8 / None / 1 / None هي افتراضات وليست تأكيدًا لمواصفات الماسح.
- اضبط الجهاز ليرسل **CR أو LF أو CRLF بعد كل مسحة**؛ يدعم القارئ كذلك إطار STX/ETX. زر «اختبار المسح» يعرض كود الباركود الوارد **من غير تسجيل أي بيع**. اختبر قطعة وعلبة وكرتونة إذا كانت لكل واحدة باركودات مختلفة.
- بعد الحفظ والاتصال، أي مسحة مكتملة **تعرض الصنف والوحدة وسعرها في شاشة المبيعات فقط**؛ الموظف يؤكد الإضافة للفاتورة بنفسه. **لا تُضاف أسطر ولا تتغير الأرصدة بشكل تلقائي من أحداث COM** لتقليل خطر البيع المكرر بسبب قراءات الجهاز.
- لو المنفذ مش موجود أو مُستخدم من برنامج آخر، سيظهر وصف الخطأ ويظل البحث اليدوي متاحًا. إذا فصلت الجهاز أثناء التشغيل، قد تحتاج إعادة توصيله وإعادة تشغيل البرنامج/حفظ الإعدادات؛ الاسترداد التلقائي من الفصل والتوصيل غير منفّذ بعد.
- اسم المنفذ المرئي في **Device Manager → Ports (COM & LPT)**، وماسح RS-232 يتطلب منفذ RS-232 أو محول موثوقًا يُظهر منفذ COM على ويندوز.

**اختبارات v0.4:** 38 اختبار SQLite ناجح؛ فحص جميع ملفات XAML كملفات XML ناجح؛ أضفنا اختبار C# مستقل لتجميع رسائل الباركود المجزأة ضمن GitHub Actions على Windows، لكن لم نشغّله على ويندوز بعد. **لم يُختبر الاتصال مع الماسح الفعلي**؛ يلزم الموديل أو صورة ملصق الجهاز وطريقة التوصيل للتحقق.

## الصلاحيات

| الدور | ما يمكنه عمله في هذه النسخة |
|---|---|
| ADMIN | جميع الوظائف وإدارة الموظفين وكلمات مرورهم |
| MANAGER | الأصناف، الوحدات، الأسعار، المشتريات، المبيعات، المخزون، التقارير والنسخ الاحتياطية؛ بدون إدارة الموظفين |
| CASHIER | عرض الأصناف والأسعار، بيع بالسعر المسجل بدون تغييره، والتنبيهات |
| STOCK | عرض الأصناف والتنبيهات، وفواتير المشتريات وتحديث حد النقص؛ بدون بيع ولا تغيير أسعار الوحدات |

عند أول تشغيل جديد يجب إنشاء كلمة مرور للمدير `admin` (10 أحرف فأكثر). لا توجد كلمة مرور افتراضية. مسؤول النظام يمكنه إنشاء حسابات وإيقافها أو إعادة تعيين كلمات مرورها. خمس محاولات خاطئة توقف الحساب لمدة 15 دقيقة. يتم تخزين تجزئة PBKDF2-HMAC-SHA256 مع salt وليس كلمة المرور نفسها. **هذه حماية دخول للتطبيق وليست تشفيرًا لقاعدة البيانات**.

### الترقية من v0.1/v0.2/v0.3

تتم الترقية إلى المخطط v4 تلقائيًا عند البدء، مع لقطة احتياطية متسقة لقاعدة قديمة قبل تغييرها. الأصناف والفواتير والمخزون السابق محفوظة، وتُنشأ تلقائيًا وحدة أساسية لكل صنف موجود.

إذا كان الإصدار v0.2 لديه كلمة مرور واحدة، تُنقل بيانات تجزئتها إلى مستخدم `admin`؛ يدخل المدير بنفس كلمة المرور السابقة. إذا لم تكن كلمة مرور سابقة مفعّلة، يجب إنشاء المدير أولًا. **استرجع من النسخة الاحتياطية عند فشل الترقية، ولا تفتح قاعدة v4 ببرنامج أقدم.**

## التشغيل والبناء

1. Windows مع Visual Studio 2022 و.NET desktop development و.NET Framework 4.8 Developer Pack.
2. افتح `src/OfflineStore/OfflineStore.csproj`، ثم Restore لحزمة `System.Data.SQLite` الإصدار 2.0.4.
3. حمّل أرشيف SQLite Windows x86 المحدد في `.github/workflows/windows-build.yml`، وتحقق من بصمته بواسطة `python scripts/verify_sqlite.py <archive>`، وضع `sqlite3.dll` داخل `src/OfflineStore/native/`.
4. ابنِ `Release x86`. التشغيل اليومي لا يحتاج اتصال إنترنت، لكن اعتماد البرنامج يستلزم اختبارًا على Windows 7 SP1 و10 و11.
5. عند الاستخدام على جهاز واحد، **حسابات الموظفين هنا داخل نفس تطبيق Windows ونفس ملف البيانات الخاص بحساب Windows الجاري**؛ إذا تم تسجيل الدخول إلى Windows بمستخدم مختلف، فإن `%LOCALAPPDATA%/OfflineStore/store.db` يكون ملفًا مختلفًا. مشاركة البيانات بين حسابات Windows تحتاج سياسة ACL ونقل موقع الملف في إصدار لاحق.
6. تدرّب على بيانات غير حقيقية. احفظ النسخ الاحتياطية خارج الجهاز واختبر استعادتها.

تشغيل اختبارات قاعدة البيانات: `python -m unittest discover -s tests -v`.

استخدم GitHub Repository **خاصًا** للمشروع ثم ارفع الملفات؛ ستشغّل `.github/workflows/windows-build.yml` اختبارات SQL وتجميع Windows وتُخرج Artifact تجريبيًا. نجاح Action على Windows Server 2022 ليس موافقة على تشغيل Win7.

## ما زال مانعًا للنشر التجاري النهائي

- دورة مرتجعات البيع والشراء، العملاء والبيع الآجل وسداد الموردين، النقدية والصندوق، الضرائب والخصومات وتكلفة البضاعة الدقيقة (متوسط مرجح/FIFO)، التقارير المالية المتحقَّق منها.
- الجرد والتسوية، طباعة الفواتير والباركود، التصدير، حسابات افتتاحية معتمدة، إجراءات استعادة كلمة المرور، والتثبيت والتحديث عبر Installer.
- اختبارات C# للمنطق والمصادقة والصلاحيات، بناء واجهة WPF، اختبارات قبول شاملة على Windows 7/10/11، اختبار النسخ الاحتياطي والاستعادة، ومراجعة أمنية قبل استخدام بيانات حقيقية.

لا نقدم وعدًا بانعدام الأخطاء؛ يجب اجتياز اختبارات إصدار محددة قبل السماح باستخدامه للمبيعات الفعلية.


## Setup.exe — نسخة تثبيت تجريبية (تهيئة المسار في v0.4.1)

**تنبيه: الملف الحالي مصدر مشروع، وليس Setup.exe جاهزًا.** أُضيف `installer/OfflineStore.nsi` وخطوات GitHub Actions لإنشاء `OfflineStore-Setup-v0.4-PREVIEW.exe` تلقائيًا بعد نجاح تجميع WPF على Windows. لا نقدر نجمع WPF أو نشغّل المُثبّت من بيئة Linux الحالية، ولم ينجح أي Build على Windows بعد.

خطوات الحصول على EXE عند توفر Repository خاص مستقل:

1. ارفع محتويات هذا ZIP إلى جذر مستودع GitHub خاص جديد للمشروع؛ لا ترفع `store.db` الفعلية، ولا كلمات سر أو بيانات عملاء.
2. افتح Actions ← **Windows EXE and Setup (PREVIEW ONLY)** ← **Run workflow**.
3. بعد نجاح كل الاختبارات وخطوات البناء، حمّل Artifact باسم `OfflineStore-Setup-Win7-10-11-PREVIEW` وفيه `OfflineStore-Setup-v0.4-PREVIEW.exe`.
4. اختبر تثبيته على كمبيوتر تجريبي يعمل بنظام Windows مع .NET Framework 4.8 مثبّتًا. ثم اختبر تسجيل الدخول والصنف وفاتورة تجريبية والباركود والنسخ الاحتياطي والتحديث وإلغاء التثبيت.

النسخة التجريبية تُثبّت البرنامج في مجلد المستخدم `%LOCALAPPDATA%\Programs\OfflineStore` وتُضيف اختصارًا على سطح المكتب وفي قائمة Start، وتظهر في قائمة إزالة البرامج. **التثبيت لا يحتاج إنترنت عند وجود .NET 4.8، لكنه لا يحمل .NET Framework 4.8 بداخله**. على Windows 7 SP1 وبعض أجهزة Windows 10 ربما يلزم تثبيت حزمة .NET 4.8 الرسمية دون اتصال مسبقًا. تُفحص النسخة أثناء تشغيل المثبّت ويتوقف بأمان إذا كانت ناقصة.

**حماية البيانات:** قاعدة البيانات عند `%LOCALAPPDATA%\OfflineStore\store.db` منفصلة عن مجلد ملفات البرنامج. الترقية فوق نفس الإصدار لا تستبدلها، وإزالة التطبيق لا تحذفها. **هذا لا يغني عن اختبار تحديث/إزالة النسخة بصورة فعلية، ولا عن نسخة احتياطية خارج الجهاز.**

**موانع التسليم النهائي:** التطبيق لا يزال بدون المرتجعات والذمم والطباعة والتقارير المالية الصحيحة، وبدون اختبار POS على الجهاز الحقيقي. `PREVIEW` للاختبار ببيانات غير حقيقية فقط. لا تسلّم للمحل على أنه نظام تجاري مكتمل. لا توقيع رقمي للبرنامج بعد؛ SmartScreen قد يعرض تحذيرًا حتى التوقيع والتوزيع الصحيحين.

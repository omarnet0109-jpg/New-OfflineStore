# OfflineStore — Engineering Code Audit & Gap Analysis
**تاريخ المراجعة:** 2026-11-03  
**الفرع محل التدقيق:** main + audit/v011-data-recovery-and-cost-integrity  
**التقنيات الفعلية:** C# WPF، .NET Framework 4.8، SQLite محلي، x86، Windows 7 SP1/10/11.

## نتيجة التدقيق
**الحكم: غير جاهز للاعتماد المحاسبي التجاري بعد.**
نجاح اختبارات Windows وبناء Setup لا يثبت صحة جميع السيناريوهات المالية أو مطابقة متطلبات البلد الضريبية.

| الأولوية | المجال | الحالة المؤكدة في المصدر | الإجراء |
|---|---|---|---|
| P0 | حساب تكلفة المبيعات | `StoreService.Post(false)` أخذ `last_cost_cents` وليس المتوسط؛ يؤدي إلى تشويه هامش الربح التاريخي | **أُصلح في هذا الفرع**؛ الاختبار يفحص اللقطة المحفوظة في الفاتورة |
| P0 | الاسترجاع | `StoreService.BackupTo` ينفذ `VACUUM INTO`، لكن زر الاسترجاع لم يكن موجودًا | **أُصلح في هذا الفرع** باسترجاع مؤجّل مع التحقق ونسخ أمان |
| P0 | تزامن التشغيل المحلي | كان يمكن فتح أكثر من نافذة مستخدم على نفس قاعدة البيانات، بما في ذلك فترة الاسترجاع | **أُصلح في هذا الفرع** بقفل `Mutex` لكل مستخدم Windows |
| P1 | سندات التوريد | موجودة كـ`SupplyVouchers` + `SupplyVoucherDetails` مع تفاصيل وآلية اعتماد واحدة؛ مسودة بدون تغيير رصيد | موجود، يستلزم اختبار الطابعة والماسح الفعليين |
| P1 | أرقام السندات | `VoucherID AUTOINCREMENT` داخل `SQLiteTransaction`، ثم `ROF-0001`؛ لا يستخدم `MAX+1` | صحيح محليًا، لا يفترض دعم قواعد SQLite على مشاركة شبكة |
| P1 | وحدات الأصناف | `product_units` يسمح قاعدة + أي عدد من العبوات ومعاملات تحويل؛ WPF `ComboBox` تتغير حسب الصنف | موجود؛ ليست `DataGridViewComboBoxCell` لأن النظام WPF |
| P1 | مستويات أسعار البيع | سعر بيع واحد لكل وحدة؛ لا توجد جداول أسعار مستقلة للجملة والتجزئة والمستهلك | **ناقص — يلزم نموذج وأسعار وصلاحيات وفحص عند الاعتماد** |
| P1 | البيع | `StoreService.Post` مع قيود قاعدة بيانات تمنع تجاوز المخزون | موجود للبيع النقدي الأساسي |
| P0 | الائتمان والتحصيل | لا يوجد نموذج مكتمل لحد العميل الائتماني وتاريخ الاستحقاق وجدول السداد والتنبيهات | **ناقص؛ لا تُسجّل مبيعات آجلة تجاريًا قبل استكماله** |
| P0 | الإتلاف | لا توجد سندات متلفة معتمدة وقيود خسارة مرتبطة بالمخزون | **ناقص؛ لا يمكن احتساب خسائر التوالف بدقة** |
| P0 | الخزنة والمصروفات | `SupplyVoucherPayments` يسجل دفعًا أوليًا فقط، بلا دفتر قبض/صرف شامل؛ مصروفات يومية ناقصة | **ناقص؛ لا يُعتمد صافي الربح الحسابي** |
| P1 | النسخ والاسترجاع | SQLite وليس SQL Server، لذا `BACKUP DATABASE` و`RESTORE DATABASE` غير قابلين للتطبيق | `VACUUM INTO` + `PRAGMA integrity_check` + استبدال آمن عند التشغيل |
| P2 | الاختصارات | F2 كان يحوّل شاشة التوريد إلى المبيعات | **أُصلح**: بحث الأصناف داخل التوريد وبيع جديد في باقي السياقات |
| P1 | الأمان | حساب المدير بدون كلمة مرور اختياري؛ قاعدة SQLite غير مشفرة | يحتاج تقوية Windows وحماية النسخ وإرشاد المستخدم |
| P1 | العمل الجماعي | نسخة الجهاز الواحد لا تعالج تنازع مستخدمين على مجلد مشترك عبر SMB | يحتاج DB خادم قبل التشغيل الشبكي؛ مجرد `busy_timeout` ليس حلًا لتزامن الشبكة |

## الملفات المكتملة/المعدلة في هذا الفرع
- `src/OfflineStore/Infrastructure/SqliteRecoveryService.cs`: الاسترجاع الكامل المؤجل، فحص سلامة النسخة، نسخة أمان مسبقة، واستبدال ذري.
- `src/OfflineStore/Infrastructure/StoreDb.cs`: الاسترجاع قبل فتح القاعدة واستعمال مدقّق سلامة واحد.
- `src/OfflineStore/Services/StoreService.cs`: لقطة متوسط تكلفة البيع وواجهة استرجاع محمية بالصلاحيات.
- `src/OfflineStore/App.xaml.cs`: منع تشغيل نسختين لدى نفس مستخدم Windows.
- `src/OfflineStore/MainWindow.xaml`: أزرار النسخ والاسترجاع والإرشادات.
- `src/OfflineStore/MainWindow.xaml.cs`: طلب اختيار النسخة وتأمين التأكيد، وتوجيه F2.
- `src/OfflineStore/Supply/SupplyVoucherControl.xaml.cs`: بحث الأصناف من F2.
- `src/OfflineStore/Diagnostics/PreviewScreenshotCapture.cs`: اختبار Windows لحساب المتوسط واسترجاع قاعدة بيانات مستخدمة فعليًا.
- `tests/test_v10_audit_recovery.py`: اختبار مسار الاسترجاع ونُظم الحماية ونسخ SQLite.

## قرارات هندسية لا يصح تغييرها دون مشروع ترحيل منفصل
1. عدم حذف سند أو فاتورة معتمدة: تصحيحها يكون بمستند عكسي مع أثر تدقيقي.
2. عدم إعادة تفسير سطور فواتير قديمة عند تعديل وحدة صنف أو سعره.
3. حفظ المبالغ بوحدات صحيحة (قروش) والكميات بأجزاء الألف، وعدم استخدام `float` أو `REAL` للمال.
4. منع «إصلاح» دفاتر قديمة بمجرّد تعديل خانة إجمالي؛ يجب إنشاء مستند تصحيح موثّق.
5. منع نقل قاعدة SQLite محلية إلى ملف مشترك في شبكة مع تشغيل متعدد المستخدمين؛ ذلك ليس SQL Server.
6. عدم تسمية إصدار الإنتاج النهائي قبل استكمال الائتمان والمرتجعات والإتلاف والخزنة والتقارير ثم تجربة الأجهزة والطباعة والنسخ والاسترجاع عمليًا.

## خطة إغلاق الفجوات بترتيب السلامة
**أ. سلامة البيانات والدفاتر:** اختبار الاسترجاع والتكلفة وتثبيت الترحيلات — الفرع الحالي.  
**ب. التسعير والائتمان:** مستويات الأسعار الثلاثة، العملاء، الحد الائتماني، مواعيد السداد، تحذيرات التحصيل.  
**ج. سندات الجرد/الإتلاف/المرتجعات:** حركات أصلية/عكسية محمية في دفاتر مترابطة.  
**د. الخزنة والمصروفات والأرباح:** سند قبض/صرف ومصروفات مرتبطة بالوثائق وإغلاق يومي.  
**هـ. بوابة الإصدار النهائي:** اختبار احتساب أرباح كامل، بيانات محاكاة كبيرة، سيناريو تعطل أثناء الحفظ، 3 مقاسات للشاشات، ماسح باركود فعلي، طابعة فعلية، استرجاع من وسيط خارجي على جهاز Windows.

## معايير إيقاف الإصدار
يُمنع توصيف النظام بأنه جاهز تجاريًا إذا كان: حساب الائتمان غير مكتمل؛ أو أي سند قد يضاعف الرصيد؛ أو النسخ والاسترجاع فشلا في الاختبار الفعلي؛ أو يمكن للمستخدم تجاوز صلاحياته؛ أو الأرباح لا تستند إلى تكلفة متسقة وتوالف ومصروفات؛ أو اختبار الجهاز الحقيقي لم يُنجز.
